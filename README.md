# Lab W3D5: vLLM Benchmark & Capacity Triage

---

## 📋 Overview
This repository contains the benchmarking and capacity evaluation artifacts for **W3D5**, executed on a Google Colab **T4 GPU** environment running **vLLM** with `Qwen/Qwen2.5-1.5B-Instruct`.

---

## 📊 Benchmark Results Summary
The automated sweep tested multiple concurrency levels against 20 fixed prompt inputs (`prompts.txt`), tracking token throughput, time-to-first-token (TTFT), p95 latency, and error rates.

| Concurrency | Tokens/Sec (tok/s) | TTFT P95 (s) | Latency P95 (s) | Errors |
| :---: | :---: | :---: | :---: | :---: |
| **1** | 61.3 | 0.072 | 2.105 | 0 |
| **2** | 113.3 | 0.080 | 2.205 | 0 |
| **4** | 5.4 | 0.155 | 2.300 | 5 |
| **8** | 0.0 | n/a | n/a | 20 |
| **16** | 0.0 | n/a | n/a | 20 |

---

## 🔍 Capacity Analysis & Knee Point
* **Determined Knee Concurrency:** `4`
* **Target P95 SLO:** `3.0` seconds
* **Limiting Factor:** **Memory / VRAM Saturation**. Higher concurrency levels (8 and 16) reach the hardware operational limits of the T4 GPU.

---

## 📁 Repository Artifacts
* `bench_report.json`: Full raw metrics and structured run history generated by `bench.py`.
* `knee.json`: Saved configuration containing the target SLO and computed optimal knee concurrency.
* `capacity-note.md`: Summary triage note detailing the limiting factors and sustainable request rates.
* `verify.py`: Automated verification script ensuring workspace compliance.
